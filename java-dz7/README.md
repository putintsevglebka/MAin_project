# ДЗ 7. Java Collections

## Как запустить

Нужны Java 17+ и Maven. Тесты запускаются из этой папки:

```
mvn test
```

Эксперимент производительности запускается отдельно:

```
mvn -q compile
java -cp target/classes homework.experiment.CollectionPerformanceExperiment
```

## Где какое задание

- Задание 1: `src/main/java/homework/list` (`CustomList`, `CustomArrayList`), тесты в `src/test/java/homework/list`.
- Задание 2: `src/main/java/homework/experiment/CollectionPerformanceExperiment.java`. Это отдельный запускаемый класс, тестов на время нет, потому что результат зависит от JVM и машины.
- Задание 3: `src/main/java/homework/registry` (`Student`, `StudentRegistry`), тесты в `src/test/java/homework/registry`.

## Результаты эксперимента

На каждый сценарий минимум 5 прогревочных запусков и не меньше секунды прогрева, затем 9 замеров, в таблице медиана. Запуск на Java 21, Apple A18 Pro.

| Операция                               | Элементов | ArrayList, мс | LinkedList, мс |
| -------------------------------------- | --------: | ------------: | -------------: |
| Добавление в конец                     |     10000 |         0.020 |          0.025 |
| Добавление в начало                    |     10000 |         3.406 |          0.025 |
| Вставка в середину (в список из 10000) |     10000 |         3.931 |        130.082 |
| Доступ по индексу                      |     10000 |         0.011 |         41.493 |
| Удаление из начала                     |     10000 |         3.833 |          0.050 |
| Удаление из конца                      |     10000 |         0.024 |          0.027 |

Добавление в конец почти не отличается: у ArrayList это амортизированное O(1) с редким копированием массива при расширении, у LinkedList выделение одного узла, и оба варианта укладываются примерно в 0,02 мс. При добавлении и удалении в начале LinkedList быстрее в десятки раз, потому что позицию искать не надо и меняются только ссылки соседних узлов, а ArrayList каждый раз сдвигает весь хвост, всего около n²/2 = 5·10⁷ перемещений ссылок. Вставка в середину показывает, что одинаковая асимптотика ещё не значит одинаковое время: в обоих списках получается около 3n²/4 = 7,5·10⁷ шагов, только у ArrayList это сдвиг, а у LinkedList проход по узлам до нужной позиции. При этом ArrayList примерно в 30 раз быстрее, потому что сдвиг идёт одним вызовом `System.arraycopy` по непрерывному участку памяти, а при проходе на каждом шаге приходится читать ссылку на следующий узел. Это и есть разница в локальности данных: шаг по LinkedList стоит примерно 1,7 нс, а перемещение одной ссылки в массиве около 0,05 нс. Такая же цена шага видна в доступе по индексу: ArrayList находит элемент за O(1), а LinkedList на каждый `get` идёт от ближайшего конца, всего около n²/4 = 2,5·10⁷ переходов, и проигрывает почти в 4000 раз. Удаление из конца дешёвое у обоих, так как нет ни сдвига, ни поиска, а порядок в этой строке менялся от запуска к запуску, поэтому считать какой-то из списков здесь быстрее нельзя. Выделение узлов в этих цифрах почти незаметно, но узлы здесь создаются подряд и лежат в памяти рядом, а в долго живущем списке они могут быть разбросаны, и проход по ним будет ещё дороже. В итоге LinkedList выигрывает только на операциях у концов списка, где не надо искать позицию, а там, где нужен индекс, лучше ArrayList.
